# 智能体通信协议（为什么出现）
我们构建了功能完备的单体智能体，它们具备推理、工具调用和记忆能力。
然而，当我们尝试构建更复杂的 AI 系统时，自然会有疑问：如何让智能体与外部世界高效交互？如何让多个智能体相互协作？

这正是智能体通信协议要解决的核心问题，它提供了一套标准化的接口规范，让智能体能够以统一的方式访问各种外部服务，而无需为每个服务编写专门的适配器。
这就像互联网的 TCP/IP 协议，它让不同的设备能够相互通信，而不需要为每种设备编写专门的通信代码。


# 通信协议
提供基于协议实现的工具接口：
* 1.MCP Tool: 基于 fastmcp 库，用于连接和调用 MCP 服务器
解决：MCP 解决的是"如何访问工具"
工具的代码无法复用、扩展性差
MCP 的设计哲学是"上下文共享"。它不仅仅是一个 RPC（远程过程调用）协议，更重要的是它允许智能体和工具之间共享丰富的上下文信息。

  * 流程
  ![MCP流程](..\..\docs\images\10-figures\10-6.png)
    * 建立连接
    * 能力发现（获取所有可用工具的描述信息（包括【工具名称】、【功能说明，LLM决定调用哪个工具】、【参数定义】））
    * 调用工具(Client 将工具列表转换为 LLM 能理解的格式，添加到系统提示词中。例如:
你可以使用以下工具：
- read_file(path: str): 读取指定路径的文件内容
- search_code(query: str, language: str): 在代码库中搜索
)



- 2.A2A Tool: 基于官方 a2a 库，用于 Agent 间通信（需要安装 a2a）
解决：解决的是"如何与其他智能体对话"
其核心设计理念是实现智能体之间的点对点通信。
在 A2A 网络中，每个智能体既是服务提供者，也是服务消费者。


- 3.ANP Tool: 基于概念实现，用于服务发现和网络管理
解决：解决的是"如何在大规模网络中发现和连接智能体"。
其核心设计理念是构建大规模智能体网络的基础设施。


# 协议使用场景
选择协议的关键在于理解你的需求：
1.如果你的智能体需要访问外部服务（文件、数据库、API），选择MCP
2.如果你需要多个智能体相互协作完成任务，选择A2A
3.如果你要构建大规模的智能体生态系统，考虑ANP


```

│ │ └── utils.py # 工具函数（create_context/parse_context）
│ ├── a2a/ # A2A协议实现（Agent-to-Agent Protocol）
│ │ └── implementation.py # A2A服务器/客户端（基于a2a-sdk，可选依赖）

│ └── implementation.py # ANP服务发现/注册（概念性实现）
└── tools/builtin/ # 内置工具模块，【工具封装层】
└── protocol_tools.py # 协议工具包装器（MCPTool/A2ATool/ANPTool）
```
